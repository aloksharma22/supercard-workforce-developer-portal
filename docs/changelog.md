# Changelog

All notable changes to the **Supercard Workforce Developer Portal** are documented on this page.

The project follows the principles of **Keep a Changelog** and uses **Semantic Versioning (SemVer)** where applicable.

This changelog records documentation updates, API improvements, feature additions, structural changes, and maintenance activities.

---

## Versioning Policy

Documentation versions follow the format:

```text
MAJOR.MINOR.PATCH
```

| Version Type | Description |
|--------------|-------------|
| **MAJOR** | Breaking documentation or API changes. |
| **MINOR** | New features, modules, or documentation sections. |
| **PATCH** | Editorial improvements, bug fixes, formatting, and corrections. |

---

# [1.0.0] - 2026-07-30

## Initial Release

This is the first public release of the Supercard Workforce Developer Portal.

### Added

- Enterprise developer portal built using MkDocs Material.
- Modular OpenAPI 3.1 specification.
- Interactive API Explorer powered by Redocly.
- Authentication guide.
- Quick Start guide.
- Error Handling documentation.
- SDK Guide.
- FAQ.
- Concepts documentation.
- Reference documentation.
- Complete REST API documentation for:
  - Employees
  - Departments
  - Attendance
  - Leave Management
  - Payroll
  - Reports
- Postman Collection.
- Custom branding.
- Dark mode support.
- Responsive documentation layout.

### Documentation

- Standardized page structure.
- Cross-linking between documentation sections.
- Enterprise writing style.
- Consistent terminology.
- Task-oriented documentation.
- Developer onboarding flow.

### API Design

- RESTful resource structure.
- OAuth 2.0 authentication.
- Standard HTTP status codes.
- Reusable OpenAPI components.
- Consistent request and response schemas.

## Documentation Maintenance

Every documentation release should include:

- Updated API examples.
- Reviewed code snippets.
- Updated screenshots (if applicable).
- Link validation.
- Grammar and editorial review.
- Navigation review.
- OpenAPI validation.
- Broken link verification.

---

## Release Process

Each documentation release should follow this workflow:

1. Update the OpenAPI specification.
2. Review affected documentation.
3. Validate internal links.
4. Regenerate the API Explorer.
5. Build the MkDocs site.
6. Perform editorial review.
7. Publish the updated documentation.
